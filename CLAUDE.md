# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A **Cocos Creator 3.8.7** project (`package.json` declares `creator.version: 3.8.7`) used as a sandbox for testing the **Cocos MCP Server** editor extension. There is no application source code yet beyond a stub component (`assets/NewComponent.ts`) and an art-asset library under `assets/Sprite/` for a casual mobile game prototype ("HotPot QDC"). The interesting surface area is the extensions, not the game.

## Architecture: the three editor extensions

All three live under `extensions/` and are loaded by Cocos Creator when the project opens. They are **distributed as prebuilt `dist/` bundles** — `extensions/cocos-mcp-v1.7.5/dist/*` is obfuscated, minified single-line JS; treat it as a binary. Do not try to read or edit it. There are no TypeScript sources in this repo for any of these extensions.

### `extensions/cocos-mcp-v1.7.5` — the focus of the project

A commercial editor extension (`cocos-mcp-server` v1.7.5, author LiDaxian) that exposes the Cocos Creator editor over an **HTTP MCP server**, so external LLM clients (Claude Desktop, Cursor, etc.) can drive the editor.

- **Transport**: HTTP server at `http://127.0.0.1:3000/mcp` (see `settings/mcp-server.json` — `port: 3000`, `autoStart: true`).
- **Tool surface**: A single `cocos_*` family of tools, each one a *router* that dispatches on an `action` field. The full enabled list and per-tool descriptions live in `settings/tool-manager.json` (the source of truth for what's currently exposed). The categories are: `scene`, `node`, `component`, `prefab`, `asset`, `editor`, `view`, `composite`, `knowledge`, `validate`, `template`, `capture`, `builder`, `animation`, `spine`, `label`. Each tool entry's `description` field contains action lists, "use X not Y" hints, and batch-operation guidance — read these before calling an unfamiliar tool.
- **Tool implementations**: `dist/tools/cocos/handlers/*-handler.js` (one handler per category, registered in `dist/tools/cocos/cocos-tools.js`).
- **Editor-side scene operations**: `dist/scene.js` is registered in `package.json → contributions.scene.methods` and runs in Cocos' scene process. The MCP server calls these via Editor IPC; this is how node/component mutations actually reach the live scene.
- **Settings UI**: `dist/panels/default` (server start/stop, port) and `dist/panels/tool-manager` (enable/disable individual tools, manage configuration slots). Panel state for tools is persisted to `settings/tool-manager.json` (`configurations[]`, `currentConfigId`, `maxConfigSlots: 5`).
- **Licensing/update**: `dist/auth/*` (`license-manager`, `device-identity`, `update-checker`). The extension phones home; the `check-license`, `activate-license`, etc. messages in `package.json` are this subsystem. Don't fight this code.
- **Client integration helpers**: `dist/mcp-client-configs.js` + the `add-to-client` / `add-to-all-clients` messages can write `mcpServers` entries into Claude Desktop / Cursor config files automatically.

### `extensions/ScriptableAsset`

Third-party extension (AILHC, v1.0.4) that adds a Unity-`ScriptableObject`-style `.sasset` data file format to Cocos. Registers an asset-db importer (`dist/importer.js`), a custom inspector section, and a right-click create menu. **Templates required by this extension live in `.creator/asset-template/typescript/`**. Source for this extension is not in the repo — only the prebuilt `dist/` and a `runtime/` directory mounted into the asset database (see `package.json → contributions.asset-db.mount`).

### `extensions/super-html`

Third-party extension (magician-f, v3.0.0) that bundles HTML/CSS/JS export functionality. Has TypeScript sources alongside its `dist/` (`extensions/super-html/tsconfig.json`, scripts `build: tsc -b` and `watch: tsc -w`) and registers global editor shortcuts (`ctrl+f`, `ctrl+g`, `ctrl+h`) — be aware these may collide with usual key bindings.

## How to work on this project

There is no build/test/lint pipeline at the project level. `package.json` is just the Cocos project marker, not an npm package. `tsconfig.json` extends `./temp/tsconfig.cocos.json`, which is regenerated by the editor — `temp/` is gitignored, so type-checking from a terminal won't work unless the editor has been opened at least once.

- **Editing project scripts** (`assets/**/*.ts`): just edit. Cocos Creator's watcher compiles on save. Cocos provides `cc` (e.g. `import { _decorator, Component } from 'cc'`).
- **Modifying MCP tooling**: you can't — the `dist/` is obfuscated. To change tool behavior, edit `settings/tool-manager.json` to enable/disable tools or rewrite a tool's `description` (which is what the LLM consumer sees).
- **MCP server lifecycle**: `autoStart: true` means it comes up with the editor. The Cocos Creator extension menu → "Cocos MCP Server" opens the control panel. From a client side, point at `http://127.0.0.1:3000/mcp`.
- **Adding the server to an MCP client**: either copy the JSON snippet from `extensions/cocos-mcp-v1.7.5/INSTALL.md` into the client config, or use the extension panel's "add to client" buttons (which call `dist/mcp-client-configs.js`).

## Conventions worth knowing

- **Asset notes**: `assets/Sprite/Sprite_Notes.md` is a hand-authored catalog (in Vietnamese) of every PNG in `Sprite/` with intended use, palette, and 9-slice candidates. Consult it before deciding how to use a sprite.
- **Engine modules**: `settings/v2/packages/engine.json → includeModules` is the canonical list of which Cocos engine modules are linked into builds (physics-ammo, physics-2d-box2d, spine-3.8, custom render pipeline, etc.). Adjust here, not in code, if you need a new module.
- **`.creator/asset-template/typescript/`** is where Cocos picks up "New Script" templates — it's also where ScriptableAsset expects its template to live.

## Things not to do

- Don't try to read or modify `extensions/cocos-mcp-v1.7.5/dist/*.js` — they're heavily obfuscated (string-array rotation + RC4-style decoder). They won't fit in context and editing them will break signatures.
- Don't edit `temp/`, `library/`, `local/`, `build/`, `profiles/`, `native/`, or `node_modules/` — all gitignored editor scratch space.
- Don't change the `port: 3000` in `settings/mcp-server.json` casually — every MCP client config in the codebase and in `INSTALL.md` assumes 3000.
